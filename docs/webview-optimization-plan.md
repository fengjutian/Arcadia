# WebView 优化方案

## 背景

桌面浏览器使用 Tauri 子 WebView 承载外部网页。React 负责标签栏、地址栏和工具面板，原生 WebView 负责网页绘制。两层 UI 独立渲染，因此标签切换、窗口缩放和面板开关必须严格同步 WebView 的可见性与边界。

当前实现已具备多标签、崩溃恢复、标签休眠、权限控制、下载拦截和滚动位置恢复，但快速切换时仍可能出现旧页面闪回、尺寸跳动和重复原生调用。

## 优化目标

- 标签切换期间不显示旧标签或旧边界。
- 同一标签的 `hide`、`resize`、`show` 按提交顺序执行。
- 过期的异步显示请求不得覆盖新的激活状态。
- 相同边界不重复调用原生接口。
- 同一帧内的多次布局通知只提交最后一次。
- 不改变阅读模式、搜索对比视图、休眠恢复和工具面板的行为。

## 第一阶段：切换与布局稳定性

### 1. 原生操作串行化

为每个 `tabId` 建立独立 Promise 队列。创建、恢复、显示、隐藏、缩放和关闭操作进入同一队列，避免异步完成顺序与调用顺序不一致。

不同标签仍可并行执行，避免一个慢页面阻塞所有标签。

### 2. 激活版本校验

每次激活标签时更新当前标签引用。执行 `resize` 后、执行 `show` 前再次检查：

- effect 尚未清理；
- 页面仍处于浏览器视图；
- `activeTabId` 仍等于目标标签。

任一条件不满足时跳过显示。

### 3. 边界去重

缓存每个标签最后一次成功应用的 `x/y/width/height`。新边界完全相同时直接返回；标签关闭或底层 WebView 丢失时清除缓存。

### 4. ResizeObserver 合帧

ResizeObserver 只安排一次 `requestAnimationFrame`，同一帧内的多次通知合并为最后一次布局结果。

## 第二阶段：生命周期与恢复

- 接入 WebView2 renderer/process failure 事件，轮询仅作为兜底。
- 创建、恢复、关闭增加显式生命周期状态：`creating/live/closing/missing`。
- 优先使用原生挂起能力；必须销毁时保存滚动位置、缩放和可恢复的导航状态。
- 根据实际内存压力和音频、下载状态决定是否休眠。

## 第三阶段：安全隔离

- 外部网页使用独立 capability，不继承宿主 UI 权限。
- Rust 命令校验调用 WebView 标签、当前 origin 和允许的命令集合。
- 密码、文件、知识库和插件命令必须在原生侧拒绝未授权来源。
- 增加跨 origin 导航后的权限状态复核。

## 验收标准

1. 连续快速点击三个标签 50 次，无旧页面闪回、重叠或明显位移。
2. 窗口连续缩放时，每个动画帧最多提交一次边界更新。
3. 重复边界不会调用 `setPosition` 或 `setSize`。
4. 标签关闭后，排队中的操作不会重新显示该 WebView。
5. 阅读模式、错误页和模态框打开时，外部 WebView 保持隐藏。
6. `npm run build`、前端单元测试和 Rust 编译检查通过。

## 本次实施范围

已完成第一阶段，并完成第二阶段中的 WebView2 进程失败事件接入：renderer 退出或无响应会立即进入标签恢复页，GPU 与辅助进程退出只记录事件、不误判为页面崩溃。原有轮询继续作为跨平台兜底。

空闲休眠现已按一分钟周期主动执行，不再依赖新建或恢复标签触发。活动标签、固定标签、未静音的音频标签和存在进行中下载的来源会被保护；清理任务带有互斥保护，避免多个 LRU sweep 同时关闭同一 WebView。

尚未实施的部分包括原生挂起、按内存压力动态休眠，以及外部网页 capability 拆分。这些功能需要独立的平台兼容与安全回归验证。
