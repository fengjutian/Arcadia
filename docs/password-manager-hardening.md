# 密码管理器强化设计

## 目标

在继续使用操作系统凭据库保存密码正文的前提下，把当前“页面加载后自动填充最近一条凭据”的基础实现升级为用户可感知、可选择、可审计的填充流程。

## 安全原则

1. 密码只在用户明确选择账号后进入网页，不因页面加载或 DOM 变化自动注入。
2. 网页只能发起“请求填充”事件，不能取得凭据列表或密码正文。
3. 主窗口负责展示账号选择器；最终填充命令必须同时校验标签、当前 HTTPS Origin 和凭据所属 Origin。
4. 设置页、SQLite、日志和事件载荷均不包含密码正文；密码继续保存在 Windows 凭据管理器等系统密钥环中。
5. 私密标签禁用保存与填充。跨域 iframe 不触发填充请求。

## 交互流程

### 填充

1. 用户在顶层 HTTPS 页面点击密码框。
2. 注入脚本仅向主窗口发送标签和 Origin。
3. 主窗口读取该 Origin 下的账号元数据并显示选择窗口。
4. 用户选择账号。
5. Rust 后端重新验证标签当前 Origin，并验证凭据 ID 属于该 Origin。
6. 后端从系统密钥环读取密码，通过受控脚本填入当前登录表单。

没有匹配账号时不弹出空窗口。程序化 `focus()`、非顶层页面和非 HTTPS 页面不触发请求。

### 保存与更新

登录表单提交后继续提示保存。若 Origin 与用户名已存在，界面显示“更新密码”，并覆盖相同凭据 ID 对应的系统密钥环条目；保存、取消或失败后立即清除前端中的密码候选。

## 分阶段范围

### 第一阶段（本次）

- 移除页面加载自动填充。
- 点击密码框后显示多账号选择器。
- 后端执行 Origin 与凭据归属双重校验。
- 保存弹窗区分新增与更新。
- 关闭弹窗后清除敏感候选状态。
- 强密码生成继续使用密码学安全随机源，并在后续迭代接入网页密码框。

### 第二阶段

- “永不保存此网站”及设置中的排除列表。
- 注册、登录和修改密码表单分类。
- 密码框内的账号建议浮层与“生成并填入”。
- 复制密码后定时清空剪贴板。
- 弱密码、重复密码和长期未更新检查。

### 第三阶段

- Windows Hello / PIN 解锁敏感操作。
- 浏览器与加密 CSV 导入、加密备份导出。
- 凭据元数据与系统密钥环的一致性检查及修复。

Windows Hello 必须通过原生系统 API 实现，不能以应用内确认框代替系统身份验证。

## 验收标准

- 页面加载和 DOM 更新不会自动填入账号密码。
- 只有真实用户点击顶层 HTTPS 页面的密码框才会打开账号选择器。
- 同一网站多个账号全部可选。
- 切换页面后，旧页面发起的选择不能填入新页面。
- 其他 Origin 的凭据 ID 无法用于当前页面。
- 私密标签、HTTP 页面和跨域 iframe 不显示选择器。
- 密码正文不写入 SQLite，也不通过账号列表接口返回。
