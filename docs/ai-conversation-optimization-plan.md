# AI 对话模块优化规划

> 状态：执行中  
> 创建日期：2026-10-30  
> 范围：`desktop/src/pages/assistant`、`desktop/src/features/ai` 及必要的本地持久化接口

## 1. 目标

把当前“能问答”的单页能力收敛成稳定、可管理、可恢复的本地 AI 对话工作区。优化遵循四个原则：

1. 会话不会因新建、切换或应用重启意外丢失；
2. 生成状态可理解、错误可恢复、长回答可控制；
3. 引用、模型和知识范围始终可见且可追溯；
4. 功能必须接入真实数据和持久化，不增加无行为的装饰按钮。

## 2. 当前能力

- 本地知识库 RAG、引用校验与通用知识降级；
- 多轮追问、问题编辑、回答重试、复制和 Markdown 导出；
- Provider/模型切换、附件、深度研究及研究记录；
- 当前会话恢复，以及最近 50 条历史会话的本机保存、恢复和删除；
- 空状态建议、加载状态、错误状态和中断状态。

## 3. 主要缺口

### P0：数据可靠性与会话管理

- 历史数据缺少运行时结构校验，损坏记录可能影响整个抽屉加载；
- 历史会话只能逐条浏览，缺少搜索、重命名和批量清理；
- 当前会话与历史会话使用两个存储键，后续应统一为版本化会话仓库；
- 附件只参与当前请求，恢复后只能保留名称或文本快照，需明确数据契约。

### P0：生成控制

- 主 RAG 回答走 `rag_answer`，当前没有对应的回答级取消命令；
- 流式聊天基础设施已经存在，但知识库对话仍主要等待整段结果；
- 因此“停止生成”不能只做前端按钮，需要 Rust 端可取消任务与流式 RAG 协议配合。

### P1：可用性

- 长会话缺少会话内搜索和快速跳转；
- 历史标题只取首问，缺少手动重命名；
- 模型切换没有展示 Provider 类型，重名模型不易区分；
- 整段导出缺少生成时间、模型和知识来源摘要。

### P1：质量与可观测性

- 回答没有“有帮助/无帮助”反馈入口；
- 缺少每轮检索模式、耗时、引用状态等可选诊断信息；
- 缺少针对多会话切换、迁移、损坏数据和并发保存的单元测试。

## 4. 分阶段方案

### 阶段 A：会话管理增强（本次执行）

- 历史列表支持关键词搜索；
- 支持会话重命名；
- 支持带确认的清空全部历史；
- Provider 选择项显示类型与模型，避免同名混淆；
- 历史空态、无搜索结果状态和按钮禁用状态收口；
- 增加纯函数和单元测试，覆盖标题、搜索与数据恢复规则。

### 阶段 B：统一会话仓库

- 建立 `ConversationRepository v2`，统一保存 active id、会话元数据和消息；
- 从 `ai.conversation.v1` / `ai.conversation.history.v1` 一次性迁移；
- 使用 schema 校验逐条容错，坏记录隔离而非整库失败；
- 保存策略增加去抖和退出前落盘，避免频繁写入。

### 阶段 C：真正的流式回答与停止

- Rust 端为 RAG answer 增加 job id、chunk 事件和 cancel command；
- 前端逐段更新当前回答，停止后保留已生成内容并标记“已停止”；
- 重试沿用同一问题和历史上下文；
- 对普通 Provider 流与 RAG 流使用统一状态机。

### 阶段 D：长会话与质量闭环

- 会话内搜索、命中高亮和消息跳转；
- 回答反馈及可选原因；
- 可折叠诊断信息：检索模式、耗时、引用状态、模型；
- 导出补充会话元数据，并支持选择是否包含来源详情。

## 5. 数据与安全边界

- 对话默认仅保存在本机，不自动同步或上传；
- API Key 继续由系统密钥环管理，不写入会话记录；
- 附件恢复只保存必要文本快照和显示名称，不保存临时文件路径；
- 删除、清空和迁移必须可预测，破坏性操作均二次确认；
- 网页与知识库正文均视为不可信输入，回答继续禁用原始 HTML。

## 6. 本次验收标准

- 可按标题和消息内容过滤历史对话；
- 可重命名单条历史，重启后仍保留；
- 可二次确认后清空全部历史，不影响当前对话；
- 同名模型能通过 Provider 类型区分；
- TypeScript 构建通过，新增及现有测试通过；
- 不改动当前工作区中与 AI 对话无关的未提交文件。

## 7. 明确不在本次实现的内容

- 不用“前端忽略结果”冒充真正的停止生成；
- 不在没有迁移与回滚方案时直接替换现有存储格式；
- 不增加联网搜索、云同步或自动读取当前网页；
- 不调整深度研究 Agent 的预算与审批模型。
